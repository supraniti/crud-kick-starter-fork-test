# Taxonomies

The user opens `Taxonomies` because they want to shape the way content is organized and discovered.

This desk should make one idea obvious from the first second: categories and tags belong together, but they do not behave the same way. Categories feel structural. Tags feel descriptive. The screen should honor that difference instead of flattening both into one generic form.

When the user lands here, they should see a clear split between the category world and the tag world. Categories should look like a living tree, something the user can understand at a glance. They can see parent and child relationships, how deep each branch goes, and how heavily each category is used. Tags, on the other hand, should feel lighter: a fast list, easy to search, easy to clean up, easy to merge when language drifts.

This desk should help with real editorial questions. Which categories are empty? Which ones are too crowded? Which tags are duplicates in disguise? Which categories already have a featured image? Which ones still need polish before they show up on category pages? These are the kinds of answers that make the desk feel alive.

Creating a new category should feel guided. The user chooses a parent if needed, sees where the new category will sit, and understands what its public identity will look like. The path should become obvious while they edit, not after they save. If the category is meant to be featured on a page, adding an image should be easy and visual, using the same gallery language as the rest of the product.

Tags should be fast and forgiving, but not messy. The user should be able to create tags in batches, clean up naming drift, merge near-duplicates, and see how many posts will be affected before making a change. If a tag is about to disappear, the desk should explain whether the user is deleting it, merging it, or just hiding it.

This desk also needs memory. If the user expands a branch of the category tree, filters to a subset of tags, and moves to page three, refreshing the screen should keep that exact view. Taxonomy work is often fiddly. Losing context is frustrating.

The best version of this desk makes the user feel like they are shaping the information architecture of the publication, not filling out a background table. It should help them keep the public world tidy and understandable.

What would make the user happy:
- Categories and tags feel like two related tools, not one awkward compromise.
- Usage counts are visible and meaningful.
- Category paths and structure are easy to reason about.
- Tag cleanup and merge flows are smooth.
- Image selection for categories feels visual, not technical.

What would make the user angry:
- A category tree that is hard to read or easy to break.
- Tags and categories buried behind the same generic form logic.
- No warning about how many posts will be affected by a change.
- Losing expanded tree state or filters on refresh.
- Having to guess how taxonomy changes affect public pages.
