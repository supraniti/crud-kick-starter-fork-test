# Media

The user opens `Media` because they want to work with images and files as living assets, not as filenames.

The first impression should be visual. A real library. Thumbnails, quick filters, useful labels, and a sense of where things belong. The user should be able to scan the screen and immediately answer simple questions: what is new, what is ready, what is missing details, what is used often, and what has never been used at all.

This screen should reward visual thinking. The user drags files in from the desktop or clicks a single clear upload button. New uploads appear quickly, not hidden behind a refresh ritual. If the user selects an image, the right side of the screen becomes a working bench for that asset: larger preview, alt text, short description, category, usage labels, and a short list of where the asset is currently used.

That usage story matters. Media should not feel detached from the rest of the product. If the user selects a hero image, they should be able to see that it is used on three posts, one category page, and maybe a layout preset. Those references should be clickable. This turns the media desk from a warehouse into a control room.

The user should be able to clean up and improve the library without friction. They can rename an image, improve the alt text, add usage hints, create a web-optimized version, make a thumbnail, or replace the source file. Replacing a file should feel safe and understandable: if an image is already in use, the system should explain whether the replacement will update those places or create a new asset instead.

The remote side of the story should also be visible without overwhelming the user. A user should not have to guess whether an image is only local or already published. The library can show a simple state: local only, ready to sync, synced, changed since sync, or missing remotely. If the user selects multiple items, bulk sync should feel natural. If one asset failed, the user should be able to see exactly which one and why, instead of being told that media failed in the abstract.

This screen is also where other desks borrow confidence. When the user is editing a post, an author, or a taxonomy entry, the media picker should feel like a door into this same library. Not a separate mini-app with different rules. If the right image is missing, the user should be able to upload it from that picker and keep moving.

The best version of this desk makes users feel organized. They are not just throwing files into a hole. They are building a library with memory, meaning, and visible publication state.

What would make the user happy:
- Upload feels immediate.
- The grid is pleasant to scan.
- Every asset shows whether it is ready, published, missing details, or stale.
- Usage is visible and clickable.
- The same gallery language appears everywhere else in the product.

What would make the user angry:
- A media desk that feels like a file browser from an old operating system.
- No way to tell where an image is used.
- No distinction between local work and published work.
- Having to leave another desk just to upload one missing image.
- A library full of tiny technical fields but no visual confidence.
