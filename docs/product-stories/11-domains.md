# Domains

The user opens `Domains` because they want a plain answer to one question: where will people actually read this?

This desk should feel public-facing from the start. Not in a design sense, but in a mental sense. The user should be thinking about addresses, trust, and visibility, not about infrastructure pieces. If the system is offering a temporary public address, that should be presented honestly. If the user is bringing a real domain, the path to making it live should be calm and exact.

The most useful thing this screen can do is turn abstract setup into recognizable examples. If the user enters a domain, they should immediately see example post links, category links, and media links. If they are still using a temporary address, they should see those temporary links too, clearly labeled as temporary. The desk should always answer the question, What will a real reader type into the browser?

When the user does bring a real domain, the instructions must be human. Exact records to create. Exact values to point to. Clear status for whether the domain is seen, whether the certificate is ready, and whether the site is reachable. The user should never be forced to decode a cloud product vocabulary just to connect a hostname.

This desk should also make honesty a feature. If a domain is not ready, it should say so plainly. If the system is using a temporary address, it should not pretend that the job is complete. If only media is reachable but not pages, the user should see that distinction. A domain desk that hides half-readiness creates more confusion than no domain desk at all.

The user should leave this screen with confidence about the public edge of the system. They should know whether they are in testing mode or real mode, what someone can open today, and what step remains if the site is not fully live yet.

The best version of `Domains` makes the public side of publishing feel concrete. Not magical, not scary, not scattered across different places.

What would make the user happy:
- Example public links appear immediately.
- Temporary and real addresses are clearly distinguished.
- Domain instructions are exact and easy to follow.
- Readiness is visible without interpretation.
- The screen tells the truth about what is already browseable.

What would make the user angry:
- A domain desk that starts with infrastructure nouns instead of actual public addresses.
- No sample links to inspect.
- Unclear distinction between temporary testing and real live access.
- Missing certificate or domain status hidden behind vague messages.
- Being told a domain is ready when actual pages are still not reachable.
