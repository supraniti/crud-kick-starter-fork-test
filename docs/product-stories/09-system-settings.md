# System Settings

The user opens `System Settings` rarely, and that should be reflected in the mood of the screen.

This is not the place where day-to-day work happens. It is where the publication sets a few wide defaults that many other desks quietly inherit. Because of that, this desk should feel calm, small, and trustworthy. It should never read like a junk drawer.

The screen should begin by telling the truth: most people do not need to live here. Most of the real setup happens in `Remotes` and `Domains`. Most of the real daily work happens in content and release desks. `System Settings` exists for product-wide defaults, fallbacks, and repair work.

That clarity should shape the whole experience. Instead of one giant form, the user should see a short set of clearly named groups. Publication identity. Language and locale defaults. Fallback social image. Default comment behavior. Default bindings that other desks will use if a page or module does not choose something more specific. Each group should explain where its effects will show up.

This screen should also respect inheritance. If a value comes from somewhere else, the user should be told that. If a value is only a fallback and is being overridden in a particular page or desk, that should be understandable too. Nothing on this screen should create a silent surprise later.

The user should feel safe changing one thing at a time. Save a section. Confirm success. Move on. If a setting is advanced or dangerous, it should be visually marked as such. If a normal operator should not touch it often, the desk should say that plainly.

The happy version of `System Settings` is not exciting. It is quiet, clear, and dependable. The user leaves feeling that the publication has sane defaults and that they know where those defaults matter.

What would make the user happy:
- The screen explains why it exists.
- There are only a few well-named groups.
- Every setting has a visible effect story.
- Section-level saves make changes feel safe.
- Inheritance and overrides are easy to understand.

What would make the user angry:
- A giant form with no hierarchy.
- Settings duplicated from other desks.
- Hidden consequences that appear later in pages or deployments.
- Advanced values mixed in with ordinary defaults.
- The feeling that this screen became a dumping ground for anything with no home.
