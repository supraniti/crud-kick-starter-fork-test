# Product Stories

These stories describe how each product desk should feel to a real operator.

They are intentionally written in natural language.
They are not implementation notes, not schema notes, and not route notes.

The point of this folder is simple:
- give each desk a human standard
- make review easier
- force the product to be judged by the experience it creates

Common standard across all stories:
- the screen should make sense when the system is empty
- the user should understand what to do next without tribal knowledge
- important state should be visible
- dangerous actions should be clear and reversible when possible
- related work should happen in one place, not across three desks
