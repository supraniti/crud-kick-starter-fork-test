# Posts

The user opens `Posts` because this is where the publication actually comes alive.

The list should feel editorial, not clerical. Titles are prominent. Status is clear. Author, category, publish timing, and page readiness are easy to scan. The user should be able to sort and filter by what matters in the real day-to-day rhythm of publishing: draft, in review, scheduled, published, archived, author, category, tag, missing image, missing SEO, not yet deployed, already live.

When the user clicks into a post, the screen should feel like one coherent writing desk. The post body is the center, but the supporting details should never feel like afterthoughts. Title, subtitle, excerpt, body, author, co-authors, categories, tags, featured image, gallery, comment policy, SEO, and publish timing should all be close enough to feel connected, yet calm enough not to overwhelm.

Media must feel native here. Picking a featured image should open the same gallery experience the user trusts from the media desk. If the correct image is missing, they should upload it from the post flow and keep going. The same goes for the gallery and the social image. The user should not have to open three modules just to finish one post.

Relationships should also feel obvious. If the user selects an author, they should see who that person is. If they add categories and tags, they should understand the organizational shape of the post immediately. If the post has a public page already prepared, they should be able to jump straight to it. If it has not been deployed yet, that should be visible without guesswork.

Revision confidence matters. Posts are not static. A user should be able to save often, publish when ready, and trust that earlier versions still exist if they need to step back. When they restore a revision, the action should feel precise, not dangerous. The desk should tell them what changed, not just that something happened.

The publishing path should feel humane. If a post is missing something important, the desk should say so in plain language. If it is ready, the path from save to review to publish should feel obvious. If a published post has not yet been released to the outside world, that should be visible too. The user should know the difference between saved here, published in the CMS, and actually live.

When this desk is right, a user can spend real time here without fatigue. They can write, enrich, correct, publish, and inspect the public outcome from one place.

What would make the user happy:
- Filters and sorting behave like a real editorial workspace.
- The editor is rich, but not noisy.
- Images and taxonomy are part of the writing flow, not side chores.
- Revision history feels trustworthy.
- The screen clearly shows what is saved, published, and live.

What would make the user angry:
- A post editor that hides important state until too late.
- Media selection that breaks focus.
- No easy jump from post to page or deployed output.
- Publishing that feels like a mystery.
- Losing filter state and selection every time the page refreshes.
