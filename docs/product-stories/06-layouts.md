# Layouts

The user opens `Layouts` because they want to shape how pages feel, not fill in design settings one by one.

This desk should feel like a studio. A canvas in the middle. Clear presets. A quiet side dock for structure and details. The user should feel invited to build, not interrogated by form fields.

The first decision should be easy: start from something sensible or continue from an existing layout. The user might choose a simple article frame, a richer hero-led page, a category landing layout, or a more compact mobile-first shape. They should see the outline of that choice immediately, not only after saving.

Dragging sections around should feel direct. Adding a hero, a content column, a sidebar, a feature row, or a call-to-action should happen where the user is looking. The labels on the canvas should speak in familiar publishing language. The user should not need to think in low-level layout jargon just to build a readable page.

The screen should reward experimentation. Change spacing, move a block, split a section into two columns, switch the viewport, preview with sample content. If the user opened the layout from a page, they should feel that they are improving that page, not entering a disconnected toy.

One thing matters a lot here: the user must be able to imagine content in the layout. Empty boxes are not enough. The canvas should show believable placeholders, real sample headings, image slots, body copy rhythm, category lists, and article metadata so the user understands what the layout will feel like once it is alive.

The right side of the story is restraint. The screen should not force every detail into permanent visibility. Advanced structure controls can live in a details area, but the main canvas should remain visual and legible. A user should be able to say, I understand this page shape, without reading a wall of settings.

Saving should feel crisp. The user knows whether the layout changed, whether it is in use, and whether returning to a page will pick up the new structure. If a layout is used in many places, the desk should say so before a risky change spreads too far.

The best version of this desk makes the user feel like they are composing reusable page language for the whole publication.

What would make the user happy:
- The canvas is the main thing, not a pile of inputs.
- Presets make starting easy.
- Sample content makes decisions concrete.
- Switching screen sizes is quick and useful.
- Returning to a page feels seamless.

What would make the user angry:
- A layout builder that is really just a technical form wearing a canvas costume.
- No sense of how real content will sit inside the structure.
- Important controls always visible, making the screen noisy.
- A reusable layout changing without telling the user where it is already used.
- Feeling lost between layout work and page work.
